## Общий вердикт

 

Код **крепкий крепкий middle** — примерно **6.5/10**. Это не студенческий проект: есть настоящая слоистая архитектура (blueprint → service → repository → model), система прав, аудит, валидаторы, реальные тесты, продуманный мониторинг. Но есть несколько реальных дыр и структурного техдолга. Для продакшена с 10–100 пользователями пригоден, для масштабирования — нет без правок.

 

## Что реально хорошо

 

- **Слоистость** выдержана: роуты тонкие, бизнес-логика в сервисах, SQL в репозиториях. Домены разнесены (device/map/user/permissions/audit/monitor).

- **Права доступа** — гранулярные (`permissions.py`, декораторы `@require_map_access`), + полный **аудит** действий.

- **Модель данных** адекватна и нормализована (IP вынесены в `DeviceIP`, индексы на месте).

- **Мониторинг** — грамотный: пул потоков, батчи, дебаунс, история статусов.

- **Фронтенд модульный** — 18 модулей карты с чёткими границами, `esbuild`-бандлы, batch-оптимизации Cytoscape.

 

## Реальные проблемы, по приоритету

 

**🔴 1. Сокеты без авторизации (это главное).** `join_room` и `request_status` ([app.py:129](app.py#L129), [:174](app.py#L174)) **не проверяют право на карту** + `cors_allowed_origins="*"` ([extensions.py:10](extensions.py#L10)). Любой аутентифицированный пользователь может подписаться на `map_<любой_id>` и получать позиции/статусы/правки чужих карт — при том, что HTTP-доступ к ним закрыт. Утечка данных в обход всей системы прав.

```python

@socketio.on("join_room")

def handle_join_room(room):

    map_id = int(room.split("_")[1])

    if not can_view_map(map_id):        # ← этой проверки нет

        raise ConnectionRefusedError("forbidden")

    join_room(room)

```

 

**🔴 2. Дефолтный пароль админа `"Admin"`** ([app.py:106](app.py#L106)) — при инициализации пустой БД. Рядом в коде есть закомментированный `secrets.token_urlsafe(8)` — надо вернуть его, а хардкод убрать.

 

**🟠 3. Масштабирование на 1 воркер.** `async_mode="threading"` без message queue ([extensions.py:11](extensions.py#L11)): при `gunicorn -w 2+` сокет-события не пересекают воркеры → часть клиентов не получит обновления. Для роста нужен Redis-адаптер (или явно зафиксировать `-w 1`). Плюс SQLite при конкурентной записи (монитор + веб) — блокировки; для многопользовательского → PostgreSQL (`DATABASE_URL` уже поддержан).

 

**🟠 4. God-файлы.** `api.py` — **1316 строк** (~40 роутов), `map_service.py` — **953**. Пора резать: `api.py` → `api_devices/links/groups/permissions.py`; `map_service.py` → `link_service/group_service/shape_service`. Цель ≤300 строк на файл.

 

**🟠 5. Фронтенд: глобальное состояние и хрупкие контракты.**

- Всё живёт в `window.*` (`cy`, `currentMapId`, `saveState`, `setSkipNextMapUpdate`…). `skipNextMapUpdate` — таймерный костыль (сбрасывается по `setTimeout`, может «отпустить» раньше времени). Стоит завести маленький `state.js` и/или request-id вместо глобального флага.

- **Дубли**: `showToast` в двух несовместимых реализациях (`base.js` и `modal/ui.js`), `getCsrfToken` в трёх местах, паттерн `fetch+CSRF` копипастой в ~15 местах. Просится `utils/http.js` (`postJSON/putJSON`) и один `showToast`.

- Динамические `import('./elements.js')` для оборачивания синхронных функций ([index.js](static/js/src/map/index.js)) — лишняя асинхронность, заменить статикой.

 

**🟡 6. Тесты тонкие.** Покрыты только валидаторы. Нет тестов на `permissions` (критичный путь!), сервисы, API-роуты, сокеты. Минимум — интеграционные тесты прав доступа.

 

**🟡 7. Техдолг-хлам.** `monitor_old.py`, `*_old.js`, мёртвый `vite.config.js` (указывает на несуществующий `main.js` — используется esbuild), закоммиченные `dist/*.min.js` (риск рассинхрона src/dist — легко забыть пересобрать). Удалить старьё; `dist` — в `.gitignore` + сборка в CI.

 

## Общие советы

 

1. **Сначала безопасность сокетов** (пункт 1) — это единственная по-настоящему срочная дыра.

2. Убрать хардкод-пароль.

3. Определиться со масштабом: если >1 воркера/много юзеров — Redis для socket.io + PostgreSQL. Если нет — просто зафиксировать `-w 1` и задокументировать.

4. Рефакторинг God-файлов и вынос HTTP-слоя/`showToast` на фронте — не срочно, но окупится в сопровождении.

5. Тесты на `permissions` — дёшево и закрывает регрессии в самой чувствительной части.
